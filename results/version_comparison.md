## 2. 策管规则:**不可比,这是核心差异**

策管后:**`src/logd` 4200 行,`src/admet` 4102 行**(2871 + 410 + 821)。少 98 个。

原因已定位到 `src/admet/qc.py:173-180`:它在**连接层(connectivity layer)**
分组去重,注释明确写着把**立体异构体与不同质子化态视为同一化合物**,
然后合并标签并保留 `label_spread` 列。

| | `src/logd` | `src/admet` |
|---|---|---|
| 去重键 | 异构 canonical SMILES(`MolToSmiles` 默认含立体) | `connectivity_key`(InChI 连接层,忽略立体与质子化) |
| 立体异构体 | **保留为不同分子** | **合并为一个化合物** |
| 质子化态变体 | 保留为不同分子 | 合并 |
| 矛盾重复测量 | 超过 0.5 log 单位则**整组丢弃** | 合并并记录 `label_spread` |
| 反离子 | 取最大片段 | 记录 `n_fragments` |
| 电荷中和 | **不做**(logD 是 pH 依赖量) | 在去重键层面忽略,但保留代表结构 |
| 最终行数 | 4200 | 4102 |

**两种选择都有道理,但它们定义了不同的预测任务:**

- `src/admet` 的理由成立:logD 对立体化学几乎不敏感,
  合并立体异构体可以消除一条近重复泄漏通道,并给出
  `implied_experimental_mae_floor = mean(spread)/2` 这个很有价值的
  实验误差下界估计(我没有做这件事)。
- `src/logd` 的理由也成立:保留全部 4200 个被实际测量的结构,
  不替任何一对异构体决定"它们是同一个化合物"。

**后果:两版的 n 不同、标签不同(一边是单次测量,一边是组内均值)、
任务难度不同。因此分数不可直接比较。**

## 3. 划分与评估协议

| 项 | `src/logd` | `src/admet` |
|---|---|---|
| 比例 | 80 / 10 / 10 | 70 / 10 / 20 |
| 实际 n | 3360 / 420 / 420 | 2871 / 410 / 821 |
| 骨架划分 | 确定性,大骨架族优先进 train | 确定性,大骨架族进 train、单例进 test |
| 划分数量 | 1 个骨架(+1 个随机,**未训练**) | **7 个**:骨架确定性 + 骨架 seed0/1/2 + 随机 seed0/1/2 |
| 划分是否用到标签 | 否 | 否 |
| 超参选择依据 | 每个划分各自 train 上 5 折 CV | **一次性**在 headline 划分的 val 上选定,其余划分复用 |
| 模型族选择依据 | 验证集 RMSE | 见第 4 节 ⚠ |
| 测试集评估次数 | **0 次** | 7 个划分 × 6 模型,全部已评 |
| bootstrap 重采样数 | 1000 | **50** |
| 主要误差指标 | RMSE | MAE |

`src/admet` 的泄漏审计(`results/tables/leakage_audit.json`)质量很高,
7 个划分全部记录了行重叠、跨划分同一性、共享骨架、最近邻相似度分布。
骨架划分均为 0 共享骨架;随机划分 255–262 个共享骨架(符合预期,
正是随机划分不该被当作泛化证据的量化理由)。
`mean_nearest_similarity` 骨架 0.483 vs 随机 0.618,把"骨架划分更难"量化了。

## 4. 泄漏与协议问题清单

### 4.1 `src/logd`(我的)——**发现一处我自己的文档造假**

| # | 问题 | 严重性 | 状态 |
|---|---|---|---|
| L1 | `train.py` docstring 原文写 "the test set is not loaded by this module at all — grep it: there is no reference to `split.test`",**这是假的**:第 64 行 `("test", split.test)` 确实读取测试集行并写入 `partition_test.csv`。我的 commit message `ce4aefa` 也抄了这个错误说法。 | **中**(文档失实;非实质泄漏) | **已修正** docstring,改为精确表述:测试集标签进入进程内存与磁盘,但从不被特征化、拟合或评分。commit 已提交无法改写,以本报告与新 docstring 为准。 |
| L2 | 立体异构体/质子化变体被保留为不同分子,**随机划分**下可能跨 train/test,构成近重复泄漏通道。骨架划分不受影响(立体异构体共享同一 Murcko 骨架,必然同属一个分区)。 | **低**(仅影响作为对照的随机划分) | 未修复。`similarity.py` 可量化,待资源允许后运行 |
| L3 | `similarity.py` 已写好但**从未运行**,所以我这边目前**没有**近重复泄漏的实测证据,只有设计论证。 | **中** | 待运行 |

**关于"测试集是否被读过"——按你的要求重新论证,不再依赖单一文件:**

不能只说 `test_access_log.jsonl` 不存在。实际证据链是:

1. **代码路径**:全仓库只有 `evaluate.py` 会对测试集计算指标。`train.py` 经 grep 确认仅在第 64 行接触 `split.test`,用途是写分区清单,之后再无引用;`_featurize_blocks` 只特征化 train 与 valid。
2. **缺失的产物有五个,而非一个**:`evaluate.py` 单次运行会产生
   `results/test_<split>.json`、`results/test_predictions_<split>.csv`、
   `results/test_table_<split>.md`、`results/figures/test_<split>_<model>.png`、
   `results/test_access_log.jsonl`。**五个独立产物全部不存在。**
3. **闸门**:`evaluate.py` 没有 `--confirm-final-evaluation` 会直接 return 2。
4. **拟合面**:所有预处理都在 sklearn `Pipeline` 内,CV 只在训练折上 fit;
   特征化是逐分子纯函数,不存在跨划分统计量。
5. **划分不依赖标签**:`scaffold_split` 只用结构分组,确定性,无 RNG。

**诚实的结论:** 测试集从未被评分,这一点由五个独立缺失产物 + 代码路径共同支持,
比单一日志强得多。但它仍**不是密码学级证明**——它依赖本会话记录的完整性。
`test_access_log.jsonl` 的真正价值在**未来**:从现在起任何一次读取都会留痕。

## 5. 为什么现在不能比分数

按你的要求不评胜负。即使评,也会是错的,因为至少五个轴不对齐:

1. **数据集不同**:4200 vs 4102,且标签语义不同(单次测量 vs 组内均值)。
2. **测试集规模不同**:420 vs 821。CI 宽度天然不同,n 更大的一方区间更窄。
3. **划分比例不同**:80/10/10 vs 70/10/20。训练数据多的一方占优。
4. **主指标不同**:我按 RMSE 选择与排序,它按 MAE。两者对离群点的敏感度不同,
   排序可以不一致。
5. **我这边根本没有测试集分数**——我只有验证集数字,而它只公布测试集数字。
   拿我的 valid 和它的 test 比较是方法论错误。

**要让它们可比,必须先统一:**同一份策管后数据集、同一划分比例与划分函数、
同一指标集、同一 bootstrap 设置。这是一次重构,不是一次对比,
而且需要先决定采用哪一套策管规则(第 2 节的两种选择)。

## 6. 建议(供你决定,我不自行执行)

**合并时值得采纳 `src/admet` 的:**
- 连接层去重(消除一条真实的近重复泄漏通道)
- `implied_experimental_mae_floor`——**这是两版里最有科研价值的一个量**。
  它给出实验误差下界;任何 RMSE 低于该下界的模型都应被怀疑过拟合。我完全没做。
- 多种子多划分评估(单一划分的分数是点估计,7 个划分给出稳定性)
- 7 个划分全覆盖的泄漏审计表

**值得保留 `src/logd` 的:**
- 测试集访问日志 + `--confirm-final-evaluation` 闸门(使协议可审计)
- 不中和电荷(保持 logD 的 pH 依赖语义)
- 矛盾重复测量整组丢弃(不制造未被测量过的标签)
- 1000 次 bootstrap
- 固定版本的容器环境(绕开 Smart App Control,且环境可复现)
- 按验证集而非测试集选择模型族

**不建议现在做:** 任何以提高分数为目的的改动。
